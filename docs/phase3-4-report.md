# JARVIS phases 3 + 4 — production report

## Outcome and scope
User authorized direct production, no staging site or full backup. Phase3 existing uncommitted code was preserved; local and live phase3 hashes matched before Phase4. Phase3 adds MC-authenticated Qwen SSE chat, Spanish CPU Piper WAV TTS, reactive blue core and separately minimized Task Executor. Phase4 adds explicit **Hablar**, **Terminar y enviar**, global **Detener** (cancel), and optional **Responder con voz (solo micrófono)**. Typed replies never auto-read. There is no auto-listen, wake word, command execution or mic-to-speaker connection.

Production: https://dashboard.microtechai.es . Assets use `20260908-chat4`; executor retains `20260908-executor3`. No changes to Nginx, MC authentication, existing model, DGX GPU/model configuration or private model tunnel in Phase4.

## Voice lifecycle
Only the Hablar click initiates getUserMedia. MediaRecorder selects supported WebM/Opus, Ogg/Opus or MP4. Recording automatically finishes at 20 seconds; 2 MiB client limit. Terminar y enviar stops every track before uploading; Detener cancels recording/transcription/model/TTS. Pagehide/logout also cancel. Late microphone permission resolutions stop their tracks; stale transcription and media callbacks are rejected by generation IDs. Listening animation takes real analyser RMS; transcribing uses the existing core bridge and existing Three.js RAF. No speech recognition service in a cloud browser is used for this new flow.

## STT backend
Authenticated `POST /api/chat.php?action=transcribe`: exact Origin + CSRF, then live MC validation before launching any worker. FormData with **only** file field `audio`; no text parameters. MIME sniffing allows WebM/Ogg/MP4/WAV, 2 MiB file limit and bounded request overhead. Server consumes no user-selected paths/URLs/model/argv. 6 requests/min/session; one global nonblocking flock; session lock released before long work.

Private handler `/opt/jarvis-stt/transcribe.php` executes fixed argv `/usr/bin/taskset -c 1 /opt/jarvis-stt/venv/bin/python /opt/jarvis-stt/stt_worker.py PRIVATE_TEMP`. No shell. Temp mode 0600 under private state directory; finally cleans file, kills/reaps unfinished process, releases lock. Wall deadline 40s; CPU rlimit 38/39s and address-space cap 2 GiB. Worker incrementally decodes with PyAV to 16kHz mono; rejects over 320000 samples **before inference**, including compressed files. faster-whisper 1.2.1, base multilingual int8, CPU1, one inference thread/worker, local-files-only `/opt/jarvis-stt/model`. No second LLM or GPU service. Model.bin SHA256 `d01c3014881c9c6f3133c182f3d2887eb6ca1c789a7538c5c007196857a0a6a9`.

Do not deploy the repository's `server/` folder under the webroot. Install those two files at the private paths above. `/opt/jarvis-stt/qa` is an isolated loopback test harness, not a staging website; its MC fixture is explicitly not production authentication. Production never points at it.

## Remaining acceptance and limits
User must sign in with own MC account, click Hablar and authorize microphone in their browser; no real user's permission was granted. Test a spoken turn and audible response on real speakers/mobile. Public authenticated full voice roundtrip and physical audibility are not claimed by isolated tests. MP4/Ogg selection supported, but real server decode here exercised WAV/WebM only. Browser timers can be throttled in background; server always rejects >20s. Abort may not interrupt PHP immediately until a SAPI detects disconnect, but worker deadline remains 40s. That worst-case timeout was code-reviewed, not measured using an intentionally hung production worker. Speech errors/silence may require retry. Per-cookie rate limits are not account-wide quotas. Old executor remains disconnected from this conversational flow and unaudited for command execution. No GitHub CI success is inferred from local tests.
